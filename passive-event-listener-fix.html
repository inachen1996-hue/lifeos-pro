🐛 Passive Event Listener Bug 修复方案

❌ 问题描述

控制台出现大量错误：

Unable to preventDefault inside passive event listener invocation.

这是因为在 touchstart 和 touchmove 事件中调用了 e.preventDefault()，但这些事件默认是 passive 的。

🔍 问题位置

在 index.html 文件中的以下位置：

  • 第 1436 行：handleTouchStart 函数
  • 第 1443 行：handleTouchMove 函数
  • 第 5647 行：计划页面的 handleTouchStart 函数
  • 第 5661 行：计划页面的 handleTouchMove 函数

✅ 修复方案

有两种修复方案：

方案1：移除不必要的 preventDefault（推荐）

对于大多数情况，我们不需要阻止默认行为，只需要移除 preventDefault 调用。

方案2：设置 passive: false

如果确实需要阻止默认行为，需要在添加事件监听器时设置 passive: false。

🛠️ 具体修复代码

修复 handleTouchStart 函数

// 修复前（有问题的代码） const handleTouchStart = (e, timerId) => { e.preventDefault(); // ❌ 这行会导致错误 setTouchEnd(null); setTouchStart(e.targetTouches[0].clientX); }; // 修复后（方案1：移除 preventDefault） const handleTouchStart = (e, timerId) => { // ✅ 移除 preventDefault，大多数情况下不需要 setTouchEnd(null); setTouchStart(e.targetTouches[0].clientX); }; // 修复后（方案2：如果确实需要 preventDefault） const handleTouchStart = (e, timerId) => { // 只在非 passive 事件中调用 preventDefault if (e.cancelable) { e.preventDefault(); } setTouchEnd(null); setTouchStart(e.targetTouches[0].clientX); };

修复 handleTouchMove 函数

// 修复前（有问题的代码） const handleTouchMove = (e, timerId) => { e.preventDefault(); // ❌ 这行会导致错误 setTouchEnd(e.targetTouches[0].clientX); }; // 修复后（方案1：移除 preventDefault） const handleTouchMove = (e, timerId) => { // ✅ 移除 preventDefault setTouchEnd(e.targetTouches[0].clientX); }; // 修复后（方案2：如果确实需要 preventDefault） const handleTouchMove = (e, timerId) => { // 只在非 passive 事件中调用 preventDefault if (e.cancelable) { e.preventDefault(); } setTouchEnd(e.targetTouches[0].clientX); };
